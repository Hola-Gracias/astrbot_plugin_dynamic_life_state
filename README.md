# DynamicLifeState - 动态生活状态插件

AstrBot 插件，用于为 Bot 生成配置时区下某个日期的全天生活状态，并在每次 LLM 请求前注入当前时段的日程与穿搭。

## 功能特性

- **自然日状态**：每份状态对应一个 `YYYY-MM-DD` 日期，范围为当天 `[00:00, 24:00)`
- **自动生成与懒加载**：每日当地时间 `00:00` 生成；当天状态缺失时，在首次对话或查询时生成
- **动态时段匹配**：支持自然时段和具体时间区间，并根据当前当地时间选择状态
- **历史状态参考**：保留最近 7 个日期的状态，生成时可参考最近若干个成功状态
- **临时上下文注入**：默认通过临时用户内容注入，不写入 AstrBot 对话历史
- **完整状态查询**：提供指令和 LLM Tool，可查询今天或指定日期的完整状态
- **会话范围控制**：支持白名单、黑名单和全部启用三种模式

## 版本变化

### v0.2.0

这是一次破坏性升级：

- 生活状态改为配置时区下某个日期的全天状态，范围为当天 `[00:00, 24:00)`
- LLM 输出字段由 `business_date` 改为 `date`，不接受旧字段别名
- 移除 `generate_time`、业务日期和业务周期，固定在当地时间每日 `00:00` 生成
- 插件初始化或重载时不主动生成；当天状态缺失时，等待 `00:00` 任务、首次对话或当天状态查询
- 提示词占位符改为 `{date}`、`{timezone}`、`{persona}`、`{history_states}` 和 `{extra_requirements}`
- 自定义提示词包含 `{business_date}`、`{cycle_start}` 或 `{cycle_end}` 时，记录警告并使用新版默认模板，但不覆盖用户配置
- 旧状态不会转换；初始化时会将旧版或无法识别的 `life_state.json` 和整个 `history/` 移入 `legacy_backup_<UTC时间戳>/`
- 备份失败时中止插件初始化并保留或回滚原文件；备份成功后保持新存储为空，等待正常生成入口

完整内容见 [v0.2.0 更新日志](changelogs/v0.2.0.md)。

## 安装

通过 AstrBot 插件管理界面安装，或将本插件目录放置到 AstrBot 的插件目录中。

插件依赖 `APScheduler`，AstrBot 安装插件依赖时会根据 `requirements.txt` 自动安装。

## 配置项

| 配置项 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `session_list_mode` | string | `whitelist` | `none` 全部启用，`whitelist` 仅列表启用，`blacklist` 列表禁用 |
| `session_list` | list | `[]` | 会话 UMO 列表，例如 `default:GroupMessage:123456`，可通过 `/sid` 获取 |
| `timezone` | string | `Asia/Shanghai` | 决定日期、每日 `00:00` 任务和当前时段的 IANA 时区 |
| `history_reference_days` | int | `3` | 生成时参考的最近成功历史状态数量，范围 0–7 |
| `llm_provider_id` | string | `""` | 用于生成状态的 LLM Provider；留空时使用当前默认 Provider |
| `persona_id` | string | `""` | 用于生成状态的人格设定；留空时使用当前默认人格 |
| `injection_mode` | string | `extra_user_content_parts` | `extra_user_content_parts` 或 `fake_tool_call` |
| `prompt_template` | text | 内置模板 | 状态生成提示词；留空或包含不受支持的占位符时使用内置模板 |
| `debug_mode` | bool | `false` | 输出生成提示词、模型返回和注入内容等调试日志 |

默认使用白名单模式。如果 `session_list` 为空，插件不会向任何会话注入状态，LLM Tool 也会返回当前会话未启用。

### 提示词占位符

| 占位符 | 内容 |
| --- | --- |
| `{date}` | 目标日期，格式为 `YYYY-MM-DD` |
| `{timezone}` | 配置的 IANA 时区名称 |
| `{persona}` | 选定人格的系统提示词 |
| `{history_states}` | 最近成功历史状态；无可用历史时为“无” |
| `{extra_requirements}` | `/dls regen` 附带的额外要求；没有时为“无” |

内置模板将历史状态和额外要求放在提示词末尾，以尽量保持前缀稳定。自定义模板不会自动补齐缺失的占位符。

## 指令

| 指令 | 权限 | 说明 |
| --- | --- | --- |
| `/dls show` | 管理员 | 查看当前时间对应的时段状态 |
| `/dls show <时段>` | 管理员 | 查看指定自然时段，例如“上午”“晚上” |
| `/dls show <HH:MM>` | 管理员 | 查看今天指定时间点的状态 |
| `/dls full` | 管理员 | 查看今天的概况、氛围和完整时间线 |
| `/dls full <YYYY-MM-DD>` | 管理员 | 查询已有的指定日期状态，不生成历史状态 |
| `/dls regen [额外要求]` | 管理员 | 强制重新生成今天的状态，可附加自然语言要求 |

## LLM Tool

插件注册 `get_full_dynamic_life_state` Tool。仅当用户明确询问全天安排、完整日程、其他时段状态或历史状态时，模型才应调用。

- 不传 `date`：返回今天的完整状态
- 传入 `YYYY-MM-DD`：查询对应日期的当前或历史状态
- Tool 与自动注入共用会话范围配置

## 工作原理

### 状态生成

1. 使用配置时区确定目标日期
2. 将其他日期的当前状态归档到 `history/`
3. 读取目标日期之前最近 N 个成功状态
4. 将日期、时区、人格、历史状态和额外要求渲染到提示词
5. 调用 LLM Provider，并校验返回 JSON 的 `date` 和时间线
6. 原子写入今天的状态；同一日期重新生成时直接替换

状态可能由以下入口触发：

- 每日当地时间 `00:00` 定时任务
- 当前状态缺失时的首次 LLM 请求
- `/dls show` 或 `/dls full` 查询今天
- `/dls regen` 强制重新生成

插件初始化或重载只加载状态和启动调度器，不会立即生成缺失状态。

并发入口共用生成锁。同一日期和时区只会生成一次，强制重新生成除外。`generated_at` 始终记录模型调用实际完成时间。

### 状态注入

- `extra_user_content_parts`：以临时 `TextPart` 注入 `<life_state>`，不写入 conversation history，推荐使用
- `fake_tool_call`：向请求上下文追加伪造工具调用消息对；Gemini Provider 自动降级为前一种方式

注入内容包含日期、时区、当前日期时间和当前时段状态。完整时间线通过指令或 LLM Tool 按需查询。

### 数据存储

```text
data/plugin_data/astrbot_plugin_dynamic_life_state/
├── life_state.json
└── history/
    ├── life_state_2026.06.29.json
    └── life_state_2026.06.30.json
```

- `life_state.json` 直接保存一个当前状态对象
- 每个历史文件直接保存一个对应日期的状态对象
- 最多保留最近 7 个有效历史文件
- 生成提示词只参考 `status == "ok"` 且早于目标日期的历史状态

### 状态数据格式

LLM 必须返回可解析的 JSON 对象：

```json
{
  "date": "2026-06-30",
  "schedule_summary": "当天整体日程",
  "style_summary": "当天整体穿搭或氛围",
  "timeline": [
    {
      "time": "上午",
      "schedule": "处理资料和消息",
      "outfit": "浅色针织衫、牛仔裤"
    },
    {
      "time": "14:00-17:00",
      "schedule": "去图书馆查资料",
      "outfit": "浅色针织衫、牛仔裤"
    }
  ]
}
```

插件持久化时会额外写入 `timezone`、`status` 和真实的 `generated_at`。

## 时间段规则

### 自然时段

| 时段 | 区间 |
| --- | --- |
| 凌晨 | 00:00–06:00 |
| 早上 | 06:00–09:00 |
| 上午 | 09:00–12:00 |
| 中午 | 12:00–14:00 |
| 下午 | 14:00–18:00 |
| 傍晚 | 18:00–20:00 |
| 晚上 | 20:00–23:00 |
| 深夜 | 23:00–24:00 |

所有区间均为左闭右开。例如 12:00 属于“中午”，14:00 属于“下午”。

### 具体区间与跨午夜

- 具体区间优先于自然时段
- `24:00`只能作为结束点，`00:00-00:00`无效
- 跨午夜范围会截断在当天结束处：`23:00-02:00`仅按`23:00-24:00`生效
- 当天`00:00-02:00`需要单独条目，或者使用“凌晨”自然时段
- 没有匹配条目时，插件临时返回“空闲”，并继承当天最近的更早穿搭

## 注意事项

- 所有会话共享一份全局生活状态，不按会话、群组或人格分别存储
- 修改人格或 Provider 不会重写已有状态，需要使用 `/dls regen` 或等待第二天
- 修改时区后，当前状态会按新时区重新生成并替换
- 时区无效时回退到 `Asia/Shanghai`
- 对采用夏令时的地区，时间线按当地墙上时钟的 00:00–24:00 解释
- 插件不读取聊天记录，也不集成天气、节日或外部日程 API

## 兼容性

- AstrBot v4.26.4+
- Python 3.10+
- 状态生成需要至少一个可用的文本 LLM Provider
