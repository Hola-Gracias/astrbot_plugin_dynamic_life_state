# DynamicLifeState - 动态生活状态插件

AstrBot 插件，用于为 Bot 生成某个日期的天气、全天生活状态，并在每次 LLM 请求前注入当前时段的天气、日程与穿搭。

## ✨ 功能特性

- **自然日状态**：每份状态对应北京时间的 `YYYY-MM-DD` 日期，范围为当天 `[00:00, 24:00)`
- **自动生成与懒加载**：每日当地时间 `00:00` 生成；当天状态缺失时，在首次对话或查询时生成
- **动态时段匹配**：支持自然时段和具体时间区间，并根据当前时间选择状态
- **历史状态参考**：保留最近 7 个日期的状态，生成时可参考最近若干个成功状态
- **节日感知**：按内置中国日历查询当天节日，用于生成日程并随状态注入
- **天气与季节**：按自然月季节模型先生成逐时段天气，再让 LLM 根据天气生成日程；同一天天气稳定一致
- **天气联动日程**：雨雪天气会带伞或安排室内活动，高温避暑、低温保暖；11 月深秋出现短袖短裤等夏装时会自动检测并重试
- **可编辑天气**：WebUI 可直接修改今天和明天的 8 个时段天气；明天预设会保存到覆写文件，等 00:00 生成日历时优先使用
- **天气恢复**：保存过的今天/明天天气可以一键恢复为内置季节模型生成的自动天气
- **临时上下文注入**：默认通过临时用户内容注入，不写入 AstrBot 对话历史
- **完整状态查询**：提供指令和 LLM Tool，可查询今天或指定日期的完整状态
- **WebUI 日程与天气管理**：插件页面可查看今天、明天和历史日程，手动编辑今天的时间线与今天/明天的天气
- **会话范围控制**：支持白名单、黑名单和全部启用三种模式

## 📦 安装

通过 AstrBot 插件管理界面安装，或将本插件目录放置到 AstrBot 的插件目录中。

插件依赖 `APScheduler` 和 `holidays`，AstrBot 安装插件依赖时会根据 `requirements.txt` 自动安装。

## ⚙️ 配置项

| 配置项 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `session_list_mode` | string | `whitelist` | `none` 全部启用，`whitelist` 仅列表启用，`blacklist` 列表禁用 |
| `session_list` | list | `[]` | 会话 UMO 列表，例如 `default:GroupMessage:123456`，可通过 `/sid` 获取 |
| `history_reference_days` | int | `3` | 生成时参考的最近成功历史状态数量，范围 0–7 |
| `llm_provider_id` | string | `""` | 用于生成状态的 LLM Provider；留空时使用当前默认 Provider |
| `persona_id` | string | `""` | 用于生成状态的人格设定；留空时使用当前默认人格 |
| `injection_mode` | string | `extra_user_content_parts` | `extra_user_content_parts` 或 `fake_tool_call` |
| `prompt_template` | text | 内置模板 | 状态生成提示词；留空或包含旧版占位符时使用内置模板 |
| `debug_mode` | bool | `false` | 输出生成提示词、模型返回和注入内容等调试日志 |

默认使用白名单模式。如果 `session_list` 为空，插件不会向任何会话注入状态，LLM Tool 也会返回当前会话未启用。

### 提示词占位符

| 占位符 | 内容 |
| --- | --- |
| `{date}` | 目标日期，格式为 `YYYY-MM-DD` |
| `{holiday}` | 目标日期的中国大陆节日名称；非节日或查询失败时为“无” |

## 🛠️ LLM Tool

插件注册 `get_full_dynamic_life_state` Tool。仅当用户明确询问全天安排、完整日程、其他时段状态或历史状态时，模型才应调用。

- 不传 `date`：返回今天的完整状态
- 传入 `YYYY-MM-DD`：查询对应日期的当前或历史状态
- Tool 与自动注入共用会话范围配置

## 🔄 工作原理

### 状态生成

1. 使用内置 `Asia/Shanghai` 时区确定目标日期
2. 将其他日期的当前状态归档到 `history/`
3. 读取目标日期之前最近 N 个成功状态
4. 根据内置中国大陆 `CN` 日历查询目标日期的节日名称
5. 根据自然月和日期生成当天 8 个时段的天气与季节上下文；如果 weather_overrides.json 中存在该日期的手动天气，则优先使用（天气先生成，且同一天保持稳定）
6. 将日期、节日、天气、季节、人格、历史状态、额外要求和可选字段清单渲染到提示词
7. 调用 LLM Provider，并校验返回 JSON 的 `date` 和时间线；必填字段缺失或类型错误的时间线条目被过滤，可选字段按注册表白名单过滤并丢弃空值
8. 检查穿搭是否与季节冲突；例如 11 月出现短袖、短裤或凉鞋时追加修正要求并重试一次
9. 原子写入今天的状态；同一日期重新生成时直接替换

节日查询固定使用 `observed=False` 和 `zh_CN`。这会排除周末顺延补假；中国调休形成、但被库正式列为公共假日的休息日仍可能返回。

状态可能由以下入口触发：

- 每日当地时间 `00:00` 定时任务
- 当前状态缺失时的首次 LLM 请求
- `/dls show` 或 `/dls full` 查询今天
- `/dls regen` 强制重新生成

插件初始化或重载只加载状态和启动调度器，不会立即生成缺失状态。

并发入口共用生成锁。同一日期和时区只会生成一次，强制重新生成除外。`generated_at` 始终记录模型调用实际完成时间。

生成失败时不会持久化失败标记，也不会覆盖已有状态：强制重新生成（`/dls regen`）失败时保留当天原有成功状态，其余入口失败时返回无可用状态。自动生成（非 `/dls regen`）每个自然日最多尝试 3 次，达到上限后自动路径不再调用 LLM，只能通过 `/dls regen` 手动重试；失败计数仅保存在内存中，插件重载（如修改配置触发重载）后自动清零。

### 状态注入

- `extra_user_content_parts`：以临时 `TextPart` 注入 `<life_state>`，不写入 conversation history，推荐使用
- `fake_tool_call`：向请求上下文追加伪造工具调用消息对；Gemini Provider 自动降级为前一种方式

两种注入方式使用相同的 `<life_state>` 文本，仅传递方式不同。注入内容包含日期、节日、季节、今日天气、当前天气、当前日期时间和当前时段状态，其中可选字段按注册表动态渲染，只输出实际存在的字段。完整时间线通过指令或 LLM Tool 按需查询。

### 数据存储

```text
data/plugin_data/astrbot_plugin_dynamic_life_state/
├── life_state.json
├── weather_overrides.json
└── history/
    ├── life_state_2026.06.29.json
    └── life_state_2026.06.30.json
```

- `life_state.json` 直接保存一个当前状态对象
- `weather_overrides.json` 保存今天和明天的手动天气覆写；生成对应日期日程时优先使用
- 每个历史文件直接保存一个对应日期的状态对象
- 最多保留最近 7 个有效历史文件
- 生成提示词只参考 `status == "ok"` 且早于目标日期的历史状态

### 状态数据格式

LLM 必须返回可解析的 JSON 对象：

```json
{
  "date": "2026-06-30",
  "schedule_summary": "当天整体日程",
  "style_summary": "当天整体穿搭或氛围",
  "timeline": [
    {
      "time": "上午",
      "schedule": "处理资料和消息",
      "outfit": "浅色针织衫、牛仔裤",
      "mood": "专注",
      "location": "家"
    },
    {
      "time": "14:00-17:00",
      "schedule": "去图书馆查资料",
      "outfit": "浅色针织衫、牛仔裤"
    }
  ]
}
```

时间线条目中 `time`、`schedule`、`outfit` 为必填字段；可选字段由字段注册表定义（当前为 `mood`、`location`、`note`）。可选字段为空的字符串、非字符串以及未注册的字段（如模型幻觉输出的其他键）会被直接丢弃。插件持久化时会额外写入由插件计算的 `holiday`、由自然月模型生成的 `weather_summary`、`season` 和逐时段 `weather`，以及 `status` 和真实的 `generated_at`。模型输出中的 `holiday` 不会被采用，模型也不能改写天气。

持久化文件保持与模型输出相同的扁平结构，可选字段直接与必填字段平级，不会嵌套成 `extra_fields` 对象：

```json
{
  "time": "上午",
  "schedule": "处理资料和消息",
  "outfit": "浅色针织衫、牛仔裤",
  "mood": "专注",
  "location": "家"
}
```


天气与季节由插件写入持久化状态，结构如下：

```json
{
  "season": "深秋",
  "weather_summary": "小雨转多云，7~16℃，南风 2级",
  "weather": [
    {
      "time": "早上",
      "condition": "小雨",
      "temperature": 9,
      "precipitation": "小雨",
      "precipitation_probability": 85,
      "wind": "南风 2级"
    }
  ]
}
```

`weather` 固定包含 8 个自然时段；旧状态没有这些字段时仍可正常加载，只会在页面和输出中显示为无天气。

### 可选字段注册表

可选字段由 `core/state.py` 中的 `OPTIONAL_TIMELINE_FIELDS` 注册表唯一定义，字典顺序即渲染顺序。注册表承担字段白名单、中文标签、渲染图标、渲染顺序和提示词字段说明的职责；后续新增可选字段只需修改该字典，无需改动解析、持久化或渲染代码。各渲染位置按注册表动态遍历：

- 历史状态参考：`- 心情：专注`（仅输出实际存在的字段）
- 临时上下文注入与 fake tool call：均为 `当前心情: 专注`，标签由「当前」+ 注册表中的中文标签组成，两种注入方式使用相同的 `<life_state>` 文本
- 指令与 LLM Tool 输出：`🙂 专注` 等，按注册表图标渲染

## ⏰ 时间段规则

### 自然时段

| 时段 | 区间 |
| --- | --- |
| 凌晨 | 00:00–06:00 |
| 早上 | 06:00–09:00 |
| 上午 | 09:00–12:00 |
| 中午 | 12:00–14:00 |
| 下午 | 14:00–18:00 |
| 傍晚 | 18:00–20:00 |
| 晚上 | 20:00–23:00 |
| 深夜 | 23:00–24:00 |

所有区间均为左闭右开。例如 12:00 属于“中午”，14:00 属于“下午”。

### 具体区间与跨午夜

- 具体区间优先于自然时段
- `24:00`只能作为结束点，`00:00-00:00`无效
- 跨午夜范围会截断在当天结束处：`23:00-02:00`仅按`23:00-24:00`生效
- 当天`00:00-02:00`需要单独条目，或者使用“凌晨”自然时段
- 没有匹配条目时，插件临时返回“空闲”，并继承当天最近的更早穿搭

## ⚠️ 注意事项

- 所有会话共享一份全局生活状态，不按会话、群组或人格分别存储
- 修改人格或 Provider 不会重写已有状态，需要使用 `/dls regen` 或等待第二天
- 日期、每日生成任务和时间线的时区均固定使用 `Asia/Shanghai`
- 插件不读取聊天记录，也不集成天气或外部日程 API
